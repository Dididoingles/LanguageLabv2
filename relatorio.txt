1. OBJETIVO DO PROJETO
--------------------------------------------------------------------------------

Refatorar o webapp Language Lab para:

- Estruturar o fluxo de páginas (hero -> login -> index -> labs -> sub-labs)
- Adicionar autenticacao via Google Sign-In
- Limitar acesso as IAs (que consomem API Groq no free tier) apenas a alunos
  cadastrados pelo professor
- Manter a chave da API Groq segura (ja esta em PropertiesService do Apps Script,
  server-side, nunca exposta ao cliente)

Decisao arquitetural principal:

- A lista de alunos autorizados fica numa planilha privada do Google Sheets
- O Google Apps Script atua como backend de validacao (nao o front-end)
- O front-end (login.html) so recebe a resposta "autorizado / nao autorizado"
- Nada de credenciais sensiveis no codigo cliente

5. ERROS ENCONTRADOS E SOLUCOES
--------------------------------------------------------------------------------

ERRO 1: "Cannot read properties of undefined (reading 'postData')"
    Causa: clicar em Executar com a funcao doPost selecionada no editor.
           doPost so funciona quando o Google chama (com POST real).
    Solucao: ignorar. Testar via debugConfig() em vez de doPost.

ERRO 2: debugConfig falhou ao abrir planilha
    Causa: USUARIOS_ID foi preenchido com a URL completa
           ("https://docs.google.com/spreadsheets/d/ID/edit?usp=sharing")
    Solucao: usar apenas o ID puro:
           "1mXNHm35jKAHcnDy1jNcQemHD06fLCxkWWmNfjNw5p6I"

ERRO 3: "Erro 400: origin_mismatch" no login
    Causa: CodePad gera URL/subdominio novo a cada arquivo criado, e
           muda sozinho sem o usuario mexer. A URL autorizada no Google
           Cloud nao bate mais com a URL atual do CodePad.
    Solucao: migrar para um host fixo (GitHub Pages / Netlify / Vercel).
             CodePad nao serve como hospedagem de producao.


--------------------------------------------------------------------------------
6. DECISAO SOBRE HOSPEDAGEM
--------------------------------------------------------------------------------

CodePad NAO SERVE para hospedar o login em producao.

Motivo: ele muda a URL/subdominio sozinho, e o Google Cloud exige origens
JavaScript FIXAS. Nao ha como autorizar uma URL que muda sozinha.

CodePad continua util como EDITOR (voce escreve la e copia para o host).

Hospedagem definitiva recomendada: GitHub Pages
    Vantagens: gratis, URL fixa, voce ja usa GitHub
    URL esperada: https://SEU_USUARIO.github.io/LanguageLab/login.html

Alternativas: Netlify, Vercel, Cloudflare Pages (todos gratis e com URL fixa)

9. OBSERVACOES IMPORTANTES
--------------------------------------------------------------------------------

- A chave da API Groq NUNCA deve ir para o front-end. Ela ja esta em
  PropertiesService do Apps Script (server-side), o que esta correto.

- O Client ID (292714518504-...) e PUBLICO. Pode aparecer no login.html sem
  problema. O que NUNCA deve aparecer e o Client Secret (que nem usamos).

- O codigo .gs nao tem nenhum ID hardcoded. Tudo vem de PropertiesService.
  Isso foi uma correcao importante: a primeira versao que eu (DS) escrevi
  tinha os IDs hardcoded na funcao setupProperties(). Corrigido.

- A planilha "Alunos Language Lab" precisa continuar privada. O Apps Script
  acessa ela via openById usando a conta que executa o script (voce). Alunos
  nunca tem acesso direto a planilha.

- Se um dia migrar as IAs do Google Sites para o seu proprio dominio, o
  sistema de login ja estara pronto para protege-las tambem. Basta as IAs
  validarem o sessionToken antes de chamar Groq.

- Token de sessao: gerado como UUID, armazenado em CacheService com TTL de
  8 horas. Se o CacheService limpar (acontece), o usuario precisa logar de
  novo. Para persistencia real, trocar por PropertiesService ou um banco.
